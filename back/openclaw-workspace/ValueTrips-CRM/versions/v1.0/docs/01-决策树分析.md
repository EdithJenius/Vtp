# 现有客服决策树分析

> 审核稿来源：Frank · ValueTrips 客服决策树（HTML 交互版）
> 审核日期：2026-05-25

---

## 一、主流程总览（6步）

```
Step A  小红书私信 → 留联系方式
Step B  加微信/拉群 → 确认身份
Step C  探需求+报价 → 必问项 → 报价
Step D  异议处理（核心战场）→ 4类异议
Step E  促单成交 → 签约打款
Step F  等待+售后 → 跟进 / 转专员
```

---

## 二、逻辑审核结论

### ✅ 认同的

| 项目 | 结论 |
|------|------|
| 6步划分 | 合理，B（加群）建议保留独立步 |
| 异议互斥性 | 4类异议（信任/产品/流程/拖延）互斥性强，可以 |
| Step A 小红书话术 | 招呼 → 产品介绍 → 引导留lxfs，逻辑完整 |
| 红线机制 | 航司员工/未成年/65+/业务边界 → 提前拦截合理 |

### ⚠️ 需要调整的

| 问题 | 原设计 | 建议改为 |
|------|--------|---------|
| 异议上转阈值 | "反复3次以上转专员" | "同样异议出现2次转专员"（新人更好判断） |
| 签约未打款状态 | 归在 Step E | 建议独立为 E.5 子步，处理逻辑不同 |
| A-R5 "我考虑下" | 留lxfs后挂起 | 加一条"隔天名额紧张话术跟进" |
| D-异议分类 | 缺"服务焦虑型异议" | 新增 D.5 "担心后续服务跟不上" |

### ❌ 遗漏的客户场景

| 场景 | 出现步骤 | 建议处理 |
|------|---------|---------|
| "我朋友/同事在你们这办过" | A | 信任度高→直接推，单独分支 |
| "帮我看看能不能办"（探一下） | A | 归入"不明确"太笼统，应独立分支 |
| "我担心后续服务跟不上" | D | 新增服务焦虑型异议话术 |
| 下卡后想转介绍朋友 | F | 推转介绍奖励机制 |
| 同行/竞对探价 | A/B | 新增红线：礼貌婉拒 |

## 三、7个拍板问题答案

| # | 问题 | 建议答案 |
|---|------|---------|
| 1 | 新人能力边界 | Step A-C 全权 + Step D 前2次异议 + Step E 签约转专员 |
| 2 | 额外转专员场景 | 客户提"改合同条款" + "我律师说..." + 报价≥5万 + 客户拿别家具体报价对比 |
| 3 | 多客户并行 | 建议"一个页面显示当前客户名+所在步骤+标签摘要" |
| 4 | 记忆功能 | 必须。新人关闭再打开能恢复——不然每天重新问一遍 |
| 5 | 话术个性化 | 统一用"我们"（团队感），可用客服花名替换"专员" |
| 6 | 红线人群补充 | 新增：同行竞对探价 → 礼貌婉拒不办 |
| 7 | 未覆盖问题上报 | 必须加"未覆盖问题"按钮，每周汇总迭代决策树 |

## 四、优化建议摘要

1. **Step A 加快节奏**：识别"朋友推荐"→ 跳过信任建立，直接推进
2. **Step C 加隐性问题**：多问一句话摸用户画像（学生/商务/高净值）
3. **Step D 按标签选话术**：同样是"太贵了"，不同人用不同打法
4. **Step F 加转介绍闭环**：下卡后不是终点，是新一轮获客起点
