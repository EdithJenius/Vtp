# PRD: CloneForge — 对标克隆笔记引擎
> 给一条对标笔记，克隆它的结构，换上你的内容

## Overview
CloneForge 是嵌入热点商机分析工具的「对标克隆」功能模块。运营人员提供一条小红书对标笔记（链接或粘贴文案），系统自动拆解其结构特征——标题模式、段落编排、语气调性、emoji 密度——然后以同样的结构框架，填入目标酒店的内容信息，生成一篇结构一致但内容全新的笔记。解决「运营不知道怎么写爆款，但知道哪个是爆款」的核心矛盾。

## Target User
小林，25岁，旅游公司内容运营。她知道什么样的笔记数据好（收藏过千的那种），但她自己写的时候总是写不出那种感觉。她更习惯的做法是：找一条对标爆款 → 把对方的主体内容替换成自己的酒店信息 → 保留对方的格式和结构。CloneForge 就是把这个过程自动化。

## Core Features

1. **对标链接解析** — 接收小红书笔记链接，自动抓取并提取文案全文（支持链接输入和手动粘贴两种模式）
2. **结构特征提取** — 分析对标文案的：标题模式（emoji 规则/长度/钩子类型）、段落编排（段数/平均段长/分隔方式）、语气调性（正式/口语/情绪）、emoji 密度与类型偏好
3. **内容映射替换** — 基于目标酒店的结构化信息（名称/卖点/价格/周边/评价），按对标结构重新填充，保持原文的节奏感和框架
4. **酒店信息库对接** — 从 Bitable 酒店资源表自动读取目标酒店的结构化数据，减少手动输入
5. **合规自动校验** — 生成后自动过 xiaohongshu_compliance.py 模块，替换违禁词
6. **多版本输出** — 同一对标结构可批量生成多个酒店的版本，形成系列内容

## User Journey
小林打开热点商机分析工具，在笔记生成模块选择「对标克隆」模式。她复制了一条最近流量很好的小红书笔记链接粘贴进去。系统几秒后返回对这篇对标文案的结构分析：标题长度12字、用了一个🌅emoji开头、正文分5段每段平均2-3行、语气偏感性、emoji密度中等。小林选定了目标酒店「丽江悦榕庄」后，系统以同样的结构生成了一篇新笔记。小林预览后觉得框架对了，微调了几个词就发布了。整个过程从「看到爆款」到「发布自己版本」不到5分钟。

## Technical Considerations

- 运行环境：Python 3.9+，集成到现有 hotspot-bitable-analysis 工作流
- 结构化特征用正则+规则引擎实现（暂不依赖 LLM API，降低每次生成成本）
- 酒店数据源：飞书 Bitable API 读取（已有模块可复用）
- 对标链接解析：web_fetch 抓取 + readability 提取正文
- 输出直接写入 Bitable「笔记裂变内容库」表
- 合规模块复用现有 xiaohongshu_compliance.py

## Success Metrics

- 运营从「看到爆款」到「生成笔记」的操作时间 < 5 分钟
- 克隆笔记发布后的互动率 >= 原始对标笔记的 60%
- 运营主动使用率：每周至少使用 3 次
- 相比模板生成，克隆模式的笔记收藏率高 20%+

## Monetization
内部效率工具，不直接产生收入。但预期效果：单个运营的日产出从 2-3 篇提升到 5-8 篇，内容矩阵扩张速度翻倍。

## Open Questions

1. 小红书链接反爬严重，直接解析不可靠——是否默认优先使用手动粘贴模式？
2. 结构特征提取的精度如何衡量——「像不像原文」谁来判断？
3. 对标克隆的笔记发布后，如果被检测为「抄袭」风险如何把控（结构和文字双重替换能否规避）？
4. 同一对标结构生成多篇后会出现「模板疲劳」吗——需要多久更新一次对标库？
5. 酒店信息库中「卖点」字段是否足够结构化——需要补充哪些字段来支撑克隆填充？
