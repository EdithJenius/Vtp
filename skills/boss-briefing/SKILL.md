# boss-briefing — 三秒读懂的管理层简报

## 为什么需要这个 Skill

grill-me 是拷问需求的。而这个 Skill 是反过来——**把已经做完的工作，压缩成老板想看的样子。**

老板不需要知道：
- ❌ 用了什么技术栈
- ❌ 过程多么曲折
- ❌ 数据分析的细节

老板只需要知道：
- ✅ 发生了什么（结论）
- ✅ 这跟我们有什么关系（影响）
- ✅ 接下来怎么办（行动）

## 输入来源

这个 Skill 会读取以下数据来生成简报：

| 数据源 | 文件路径 |
|:-------|:---------|
| 热点商机总览 | Bitable 主表（hotspot-bitables） |
| 上游产业链情报 | route-analysis/data/ |
| 笔记裂变产出 | hotspot-bitable-analysis/data/ |
| 每日混合简报 | hotspot-bitable-analysis/data/briefing_*.md |

## 使用方式

三种触发方式：

```
# 1. 今日速报
/boss-briefing

# 2. 本周周报
/boss-briefing --weekly

# 3. 专项汇报：基于某个热点/议题
/boss-briefing --topic "稻城亚丁事件商机分析"
```

## 核心原则

1. **一句话原则** — 每条信息不超过一行，多出来的都是噪音
2. **结论先行** — 先给结论，再给依据，不给过程
3. **宁短勿长** — 老板觉得不够会问，不要主动塞细节
4. **不写数字细节** — 不要说「6个信息源日均130条」，说「情报体系已建立」就够了
5. **有行动建议** — 每条发现后面必须跟「所以我们该怎么做」
6. **不加粗** — 老板在一堆加粗里找不到重点
7. **不加emoji正文** — 标题用▎分隔就够了，不要用🔥⭐装饰正文
8. **链接放最后** — 想看细节的自己点，不打断阅读流

## 与 grill-me 的关系

```
grill-me       → 跟团队拷问需求（过程导向）
boss-briefing  → 给老板汇报结论（结果导向）
hotspot-skill  → 中间的执行层
```

三件套：先拷问 → 再执行 → 最后汇报。
